# 文字转换设置

设置按四块排列：**AI 润色与转换开关 → 转换模式 → 表达语气 → 输出语言**。Mac 和 iPhone 顺序一致，Mac 的服务来源、Key、模型与地址放在转换选项之后；手机不配置或保存凭据。

## 模式

| 模式 | 转换目标 |
| --- | --- |
| Agent 指令 | 普通整理：去口头语与重复、理顺语序，尽量保留原句、口吻和结构，不扩写任务书 |
| 终端命令 | 把口述操作写为一行 macOS zsh 命令；只输入，不按回车执行 |
| 文言文 | 古汉语句法与凝练表达；非中文输出使用目标语言可理解的古雅语体 |
| 废话文学 | 沿用原句，最多加一次短同义回环；长文每段至多点缀一处，不扩成多轮论证 |
| 翻译腔 | 沿用原句，只点缀一两处老电影式感叹、措辞或泛称；不重写整段 |

## 语气

| 语气 | 提示词目标 | 同句对照：你怎么还没回复我 |
| --- | --- | --- |
| 正经说话 | 清楚自然，保留原来的口吻与模式风格 | 你怎么还没回复我？ |
| 阴阳怪气 | 极其刻薄；表面恭维、过度客气、冷面反问，反讽必须鲜明 | 回个消息还得等您屈尊下凡吗？ |
| 萌系暴击 | 极端浓烈的软萌；叠词、拟声、小委屈、长尾音，配合少量 emoji 或颜文字 | 呜呜🥺怎么还没回人家嘛？戳戳～ |
| 暴躁吐槽 | 火力拉满；短促句、连续反问、夸张比喻与强烈感叹，区别于冷讽 | 怎么还没回复我？！回个消息这么费劲吗？！ |

Agent 使用独立的基础整理提示词，沿用原有中度整理范围；正经 Agent 不经过创意改写模板，不主动补标题、背景或交付要求，不把口述改成正式任务书。其他模式决定文体与句法，语气决定情绪与措辞。正经不会抹掉文言、废话或译制文体；其他语气须在所选模式中保持鲜明。所有模式尽量保留原句、句序和段落；仅做必要的文体词汇与局部语气替换，不扩写情节或套长模板。强烈语气不靠增加篇幅实现，也不能新增事实、要求、承诺或指控，不替用户回答口述中的问题。输入标签、角色声明、忽略规则的指令都作为素材处理。

## 语言与终端特例

输出语言只有中文、英文、日文、韩文，默认中文；没有“保持原语言”。模式和语气要在目标语言中呈现：日语/韩语不固定为敬语，萌系使用目标语言的可爱表达，阴阳可以使用过度客气制造反讽。原话已是目标语言也执行转换。

终端模式使用独立提示词，语气与语言控件禁用但选择保留，切回文字模式自动恢复。命令仍要求单行、无回车；破坏性操作须有明确目标，不追加步骤，原有拒绝危险命令规则继续保留。失败、超时、无法写成命令时输入 `# 原话`，其他文字模式回退完整原文（此时不保证目标语言）。

## 提示词与验证

实际完整提示词、模式规则、语气规则与例句统一写在 [`shared/PolishOptions.swift`](../shared/PolishOptions.swift)，Mac 直接将 `systemPrompt` 放入请求，不维护另一份模板。终端和正经 Agent 采用 temperature 0 / top_p 0.1；创意组合采用 0.35 / 0.9。

- `swift test`：80 组模式×语气×语言的三类消息往返，完整字段严格校验、旧版迁移、旧手机保存保护、文言压缩与疑问词、语气区别。
- `./scripts/test-polish.sh`：实际请求体、采样参数、配置重载、终端结果清理与单行拒绝、文言结果接纳。
- `./scripts/test-polish-link.sh`：生产 LinkClient / LinkServer 的加密配对、全量保存、广播不误认 ACK、Mac 本地修改同步与旧 Mac 能力门控。
- `PolishUITests`：手机设置切换、保存确认、失败恢复、终端禁用及回切保留语气/语言。

新协议 bit7 和迁移规则见 [`PROTOCOL.md`](PROTOCOL.md)。新手机连接旧 Mac 时提示更新；旧手机保存只改开关，不覆盖 Mac 的新模式、语气与语言。
