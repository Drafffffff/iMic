## 1. 现在的问题（用户原话：「新手引导简直烂爆了」）

查看 `docs/reviews/english-ui/ios-pro-onboarding-*.png` 可以看到现状：

- **步骤太多**：WELCOME → MAC → LINK → PAIR → 5 张练习卡 → READY，共 10 屏，每屏都有几段说明文字。
- **用的不是真实组件**：练习页的「HOLD TO SPEAK」是灰色按钮，不是主页那条橙色录音横条；没有中间的弦，用箭头和手指图标代替手势；「MAC / PRACTICE ONLY」是一个假的文本框；LINK 页画了一个假的系统权限弹窗。
- **学完和真用对不上**：引导里练的界面和真正的主页长得不一样，用户进入主页后要重新理解一遍。
- **界面拥挤**：标题、像素标签、段落说明、编号步骤、按钮、次要链接都挤在一屏。

## 2. 设计原则

1. **在真实主页上教学。** 引导的主体就是 `HomeView` 本身：真实的录音横条、真实的弦、真实的 HUD、真实的波形和文字动画、真实的触感和音效。引导只是在上面加一层轻量的提示（coach mark），不另画一套界面。
2. **做一下就会，不靠读。** 每一步只有一句话（不超过 16 个汉字或 8 个英文单词），用户完成动作就自动进入下一步，不需要点「下一步」。
3. **先试手感，再做设置。** 没有 Mac 也能先玩；配对、权限放在用户已经感受到价值之后，并且在需要的那一刻才出现。
4. **界面干净。** 一屏只有一个焦点：一个被高亮的真实组件 + 一句提示 + 一个跳过入口。没有段落、没有编号列表、没有装饰插图。
5. **随时可退出、可重来。** 每一步都能跳过；设置里能重新播放引导。

## 3. 新的流程

```
欢迎（1 屏） → 在真实主页上练习（3 个必学动作 + 可选） → 连接 Mac（1 个页面，含配对） → 第一次真实输入 → 完成
```

### 3.1 欢迎（1 屏）

- 背景是**真实主页**，整体压暗约 60%，弦在后面保持环境动效（遵守减少动态效果）。
- 中间只有：iMic 字标、一句话「一只手机，接管所有输入。」（英文：「One phone. Every input.」）、一个主按钮「开始」。
- 底部一个次要文字链接「我已经用过 iMic」→ 直接进入连接 Mac。
- 不要列功能清单。

### 3.2 在真实主页上练习

进入真实主页，处于**练习模式**（见第 4 节）。顶部状态区显示 `PRACTICE` 像素标签（代替连接状态），说明这是练习、不会输入到电脑。

每一步：被教学的真实组件高亮（周围压暗，组件保持原样可操作），旁边一句提示，配一个简短的手势示意动画（半透明手指沿真实路径移动一次，然后停住）。

| 步骤 | 高亮的真实组件 | 提示（中文 / 英文） | 完成条件 |
|---|---|---|---|
| 1 按住说话 | 底部橙色录音横条 | 按住横条，说一句话 / Hold the bar and speak | 按住超过 0.5 秒 |
| 2 松手 | 同上 | 松手，文字飞向电脑 / Release to send | 松手。此时**用真实的识别结果动画**：预设的练习句子（例如「明天下午三点开会」）逐字升入弦中、飞行、落定，状态显示与真实使用一致（例如 `DONE`、已填入练习） |
| 3 下拉发送 | 中间的弦 | 下拉弦再松开，发送 / Pull the string to send | 真实的下拉松手手势触发（复用现有手势识别与弹射动画、音效、触感） |

完成 3 步后，弹出一个很小的底部卡片：「还有更多手势」（上拨删字、左右移光标、拉到顶清空、上滑取消），带一个「看看」和一个「之后再说」。选「看看」则按同样方式逐个练习这 4 个手势，每个都可以跳过；选「之后再说」直接进入下一步。

**练习中的文字落点**：不画假的 Mac 文本框。练习句子出现在主页上真实使用时会出现结果的位置（例如结果预览/状态区），和真实使用完全一致。如果确实需要让用户看到「删字、移光标」的效果，在主页现有的结果区域内展示练习文本的变化，不新增一个假的窗口。

### 3.3 连接 Mac（1 个页面）

合并原来的 MAC、LINK、PAIR 三屏。使用**设置里已有的连接电脑页面的真实组件**（`DevicesView` 或现有的连接/配对 UI），而不是另画一套：

- 页面一打开就是一句话：「打开 Mac 上的 iMic」/「Open iMic on your Mac」，下面是真实的附近 Mac 列表。
- **本地网络权限**：在页面出现、开始搜索的那一刻由系统弹出真实权限框。弹出前只用一行小字说明「需要允许本地网络，才能找到你的 Mac」。删除假的权限插图。
- 找到 Mac：点选后进入真实的 6 位配对码输入（复用现有配对组件），输完自动连接。
- 没找到 Mac（例如 5 秒内为空）：列表下方出现一行「Mac 上还没有 iMic？」，点开是一个简洁的底部卡片：接力/共享/复制下载链接（复用现有 `OnboardingLinks` 的能力），加一句「装好后回到这里」。
- 底部「稍后再连接」→ 直接进入真实主页（非练习模式，未连接状态），以后可在主页顶部的电脑入口连接。

### 3.4 第一次真实输入

连接成功后，回到**真实主页（正式模式）**：

- 一句提示：「在 Mac 上点进任意输入框，按住说话」/「Click a text field on your Mac, then hold to speak」，高亮录音横条。
- 用户第一次按住时，才请求**麦克风权限**（真实系统弹窗，弹出前的一行说明沿用现有文案）；语音识别权限（用于实时预览，可拒绝）在第一次成功输入后再请求，或保持现有时机，以不打断为准。
- 第一次真实输入成功（Mac 返回结果）后，显示一个短暂的完成提示（约 2 秒自动消失）：「完成。以后就这样用。」/「That's it.」，然后引导结束。
- 如果失败（例如 Mac 没有焦点、权限不足），沿用主页已有的真实错误提示，不另做一套。

### 3.5 完成与重来

- 引导完成后写入完成标记；已经配对过的老用户不再看到引导。
- 设置里保留「使用教程」入口，点开从 3.2 练习开始（不重复欢迎页和连接）。
- 进行中的引导在 App 被杀掉后能从当前步骤恢复（沿用现有 `OnboardingCoordinator` 的恢复能力）。

## 4. 练习模式的实现要求

- 练习模式是 `HomeView` / `SessionModel` 的一个状态，**不是**另一个页面。主页所有视觉、动画、音效、触感都走真实路径。
- **不开麦克风、不请求麦克风权限、不连网、不向 Mac 发送任何内容**。按住时，用预设的练习句子驱动实时文字与波形（可以复用 `PracticeSession.swift` 的逻辑，以及现有 DEBUG 演示中「用预设文本驱动真实动画」的做法；但练习模式必须在 Release 构建中可用，不能依赖 `#if DEBUG` 或 `--demo-script`）。波形可以用合成的、看起来像说话的频谱，不要静止。
- 手势识别、弦的物理、弹射、触感、音效完全复用现有实现，不能复制一套物理代码。
- 练习结束或退出时，清理所有练习状态，回到正常的连接/未连接状态，不残留任何文字或标记。
- 现有的 `PracticeSession.swift`、`OnboardingView.swift` 中不再需要的假组件（灰色按钮、假 Mac 文本框、箭头手势图、假权限插图）删除。

## 5. 提示层（coach mark）的视觉规范

- 压暗层：黑色 55–65% 透明度；被高亮的组件区域保持原样（用遮罩挖空，圆角跟随组件），可以正常触摸。
- 提示文字：系统字体，17pt，象牙白；放在高亮组件的上方或下方，不遮挡组件和手指操作区域。
- 手势示意：半透明象牙白圆点（约 44pt），沿真实手势路径移动一次，然后淡出；减少动态效果时改为静态箭头，不循环。
- 进度：右上角一行很小的像素字，例如 `1 / 3`；不要顶部进度条。
- 跳过：左上角或右上角一个文字按钮「跳过」/「Skip」。
- 橙色只用于状态和交互强调（遵守 `AGENTS.md`），提示层本身不用大面积橙色。
- 中英文文案都写进 `ios/iMic/Localizable.xcstrings`，遵守 `AGENTS.md` 的本地化规则；运行 `python3 tools/check-l10n.py`。

## 6. 可访问性

- VoiceOver：每一步的提示作为可朗读的元素，高亮的组件保持原有可访问性标签与操作；手势步骤提供可替代的操作（例如 VoiceOver 下双击执行，或提供「跳过此步」）。
- 动态字体：提示文字随动态字体放大不截断。
- 减少动态效果：不播放手势示意动画与环境动效，改为静态。
- iPhone SE 小屏：所有步骤不遮挡、不溢出。

## 7. 不要做的事

- 不改 `AudioCapture.swift`，不改协议，不改 Mac 端。
- 不在练习模式中打开麦克风或连网。
- 不在 Release 构建中依赖任何 `--debug-*`、`--ui-preview` 或 DEBUG 代码路径（预览参数可以用于截图，但功能本身必须在 Release 中工作）。
- 不新增假的系统弹窗插图或假的 Mac 窗口。
- 不构建到真机。
