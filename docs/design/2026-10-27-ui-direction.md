工作分支：`codex/ui-phosphor-wireframe`
阶段：完成代码预览后，已按确认方向接入原版 iOS 主界面的荧光与轻 CRT 材质。

品牌方向：中文名「恶魔低语」。英文辅标 `DEVIL'S WHISPER` 为讨论中的候选，尚未更改应用名称或标识。

## 当前优先路线

用户反馈后，优先回到原版 iOS 的像素 UI，在既有字标、状态、刻度弦和切角录音条上尝试辉光与轻 CRT，并做少量间距和层级优化。独立预览位于 [`design/original-phosphor-v2`](../../design/original-phosphor-v2/README.md)，端口 8745，可切换无效果、辉光、辉光 + CRT。原生接入继续保留现有完整释放反馈，并删除两处常驻说明；实现及验证见 [原生接入记录](2026-10-27-native-phosphor.md)。V.01 保留用于参考。

## 方向结论

建议以「复古科学工作站 / 荧光矢量线框」为统一方向。检索名称可用 Retro Scientific Workstation、Phosphor Vector Display、Wireframe FUI。这是对本项目方向的描述，不是一个有唯一规范的风格分类。

组合方式：**新增音频仪器参考的基础控件 + 图 3 的界面组织 + 图 1 的三维线框结构 + 图 2 的屏幕发光材质。**

当前界面已经具备像素字、黑底、橙色、弦和局部刻度；下一轮重点是明确的三维结构、发光线条的层次、面板之间的组织关系。装饰应来自可解释的设备结构和真实反馈。

新增长图以细线图标、窄体数字、频谱曲线、包络、旋钮、接线节点和少量等距线框物体组成。它与语音、录音、信号传输的功能有直接关联，适合作为基础 UI 组件的主要参考。

| 图中语言 | 在恶魔低语中的转化 |

| 细长数字与紧凑技术标签 | 录音时长、状态和少量必要读数；中文说明保留正常阅读字重 |
| 波形、包络、节点 | 继续由真实频谱、文字到达和拉弦张力驱动主体及局部反馈 |
| 开放框线与轻量选中边框 | 润色选项、辅助操作和设置分组；选择变化不改变页面几何布局 |
| 简洁几何线框图标 | 统一录音、设备、设置和结果的图标笔画、端点与线宽 |

配色沿用蓝色结构、橙色动作、少量绿色确认及冷白文字。参考图中的多色组合用于理解层次，不自动增加新的产品语义色。

这张参考的线条原图很清楚，适合先建立清晰的矢量组件，再分层加入显示材质。主体采用较明显的荧光晕，控件采用轻微线芯光，中文保持清楚。描边视觉可以细，触摸区域仍保持至少 44pt；图中的控件集合需要按手机真实功能筛选和分组。

「恶魔」的品牌意象优先藏在字标尖角、波形轮廓和释放时的局部反馈中；「低语」通过安静的待机呼吸、细线和声音接收节奏表达。名称与音频仪器风格共同构成私密通讯设备的气质。

## 画面语言

### 主体与基础 UI

- 主体继续围绕弦，发展为带真实空间坐标和轻微透视的 3D 声场线框体。先保留环列识别度，再比较网格连线和截面形式。
- 录音、音量、频谱、拉弦张力、文字落点与弹射共同驱动这一主体。模型变化应有对应的交互或数据意义。
- 主体保持稳定的交互朝向；相机和空间投影需要与手势命中、文字落点共用几何数据。
- 按钮、开关、面板边框、分隔线和图标使用普通二维线框。可采用开放边框、局部缺口和端点标记。
- 手机上保持「设备与状态—声场主体—主操作」三层；设置页以标题、字段、说明、辅助入口形成层级。
- 界面密度采用「主体区域丰富、操作区域明确、辅助信息安静」的分配方式。图 3 的桌面多面板密度需重新适配手机。
- 图标统一线宽，文字保留英文技术标签与清晰的简体中文。像素字用于品牌和有限的技术读数。

### 初始色板与语义

以下是待原型比较的起始值，不是已经确认的最终 token。

| 角色 | 起始颜色 | 用途 |
| --- | --- | --- |
| 背景黑 | `#050505` | 保留现有黑底与大块留白 |
| 结构暗蓝 | `#18345C` | 远处线框、低权重框线和坐标参考 |
| 荧光蓝 | `#4C8DFF` | 主要空间结构、活动中的声场、可交互线条 |
| 荧光橙 | `#FF5B18` | 按下、拉弦蓄力、释放与关键选中状态 |
| 信号绿 | `#82E6A2` | 少量连接确认、有效信号或成功标记 |
| 近白 | `#DCE5E4` | 正文、关键读数和最亮的线芯 |

蓝色承担结构，橙色承担动作，绿色承担少量确认。状态同时保留文字、形状或标记，颜色不独自承载含义。橙色继续用于局部交互和强调。

### 荧光感的构成

1. **清楚的线芯**：细而稳定，保留实体结构和字形。刻度与边框继续对齐物理像素。
2. **贴近线芯的光晕**：同色、较窄，用于表达发光材料。
3. **低强度外溢光**：主要集中在声场主体和活动焦点，黑色背景保持干净。
4. **深度亮度**：近处更清楚、更亮；远处适度衰减，交点可以小范围提亮。

需要同时检查线宽、亮度和光晕半径。单纯扩大模糊会使空间结构和中文混在一起；单纯提亮颜色会缺少发光材质。

## 复古显示效果的强弱分配

| 效果 | 初始建议 |
| --- | --- |
| Bloom / 磷光晕 | 主要材质，优先作用于线框和交互焦点；保留清楚线芯 |
| 扫描线 | 弱、细、稳定，按屏幕物理像素处理并检查摩尔纹 |
| 磷光点阵 | 很低强度，先与扫描线分开比较，再决定是否叠加 |
| 色散 / 色边 | 仅在高亮图形边缘少量使用；中文正文和系统状态栏保持清楚 |
| 余辉 | 只在模型变化和信号运动上短暂保留，参数按时间计算；与现有文字快门曝光分开，避免双重拖影 |
| 噪声 | 低对比、静态或缓慢变化；保持可控，避免逐帧随机闪烁 |
| 曲面畸变 | 首版关闭，保留直线框架和准确的触摸位置 |

图 2 同时包含矢量式光线和栅格式扫描纹，是可借鉴的视觉混合。真正的矢量 CRT 本身没有常规栅格扫描线；Libretro 对 vector-glow 的说明也明确了这一点。[来源](https://docs.libretro.com/shader/crt/#vector-glow)

## RetroArch / Libretro shader 候选

用户提及的「roch arch」在本轮按 RetroArch 理解。已查阅公开的 `libretro/slang-shaders` 及官方文档。

| 候选 | 已核实内容 | 对 iMic 的建议 |
| --- | --- | --- |
| [vector-glow](https://github.com/libretro/slang-shaders/blob/master/crt/crt-effects/vector-glow.slangp) | 用于矢量显示光晕与余辉；当前预设为 10 passes，包含反馈纹理、模糊与合成 | 最贴近想要的荧光线框质感；拆解其效果做小范围原型，再决定移植哪些阶段 |
| [crt-lottes](https://github.com/libretro/slang-shaders/blob/master/crt/shaders/crt-lottes.slang) | 单 pass 预设；源码提供扫描线、mask、bloom 与曲率参数；作者标注 Public Domain | 可作为显示材质的移植起点；先关闭曲率和强 mask，分别比较扫描与 bloom |
| [zfast-crt](https://github.com/libretro/slang-shaders/blob/master/crt/zfast-crt.slangp) | 单 pass；实际入口为 `crt/shaders/zfast_crt/zfast_crt_finemask.slang`，其 include 声明 GPL-2.0-or-later | 轻量扫描纹与 mask 的备选。官方把它列为适合低性能或移动设备的候选；iPhone 的实际开销仍需测量 |
| [crt-royale](https://github.com/libretro/slang-shaders/blob/master/crt/crt-royale.slangp) | 当前基础预设为 12 passes，涵盖更完整的 CRT 显示建模 | 用于比较显示材质的上限；移动端首轮优先测试更小的效果链 |

重要的源码细节：`vector-glow` 当前的 `glow-trails0.slang` 用 `frame.rrr` 参与亮度计算。对以蓝色为主要发光色的设计，这会让余辉响应依赖红色通道；蓝、橙亮度需要单独测试。不能直接假定现有预设的余辉能正确覆盖新的配色。[源码](https://github.com/libretro/slang-shaders/blob/master/crt/crt-effects/shaders/glow-trails/glow-trails0.slang)

Slang 支持 Metal 目标，但 `.slangp` 是预设和多 pass 管线描述，不能直接作为本项目的 `.metal` 文件加载。需要移植着色代码及相应纹理、参数和 pass 管理。各 shader 及 include 的来源与许可需按最终采用文件保留。[官方开发说明](https://docs.libretro.com/development/shader/slang-shaders/)

## 与现有工程的衔接

- 当前主图由 SwiftUI Canvas 绘制，文字有独立的 `CAMetalLayer` 与 Metal 管线；完整显示后处理需要先验证这些层的合成方式。
- 初期优先对声场图形做荧光与显示材质原型，基础 UI 通过统一线框、字阶和局部发光建立同一视觉语言。
- 保留现有麦克风图标资产、按住录音、拉弦、文字落点和弹射的核心识别度；本阶段评估不改协议、输入与权限逻辑。
- 继续使用共享显示时钟；无操作 40 秒后用 4 秒收住环境动效，隐藏/后台立即暂停。静态 mask 和颗粒不独立保活。
- 新的光晕和余辉需同时验证中文清晰度、密集线框重叠、暗色界面细线、减少动态效果与长文本弹射。
- 具体 GPU pass 数、纹理尺寸和帧率以真机测量为准，当前未对新 shader 作性能承诺。

## 原型推进顺序

中心波形的真 3D 与完整动效衔接另见 [三维实现评估](2026-10-27-waveform-3d-plan.md)。

首版代码位于 [`design/phosphor-v1`](../../design/phosphor-v1/README.md)，本地预览端口为 8744。已实现 WebGL 2 三维圆环与深度、双尺度辉光、显示纹理开关、正/侧/斜视、合成信号录音、文字附着与拉弦弹射、设置布局。该原型用于确认构图和运动方向，尚未完成原生完整动效迁移，具体边界见原型 README。

1. 代码制作同一构图的两档材质样张：「清晰线框」与「荧光显示」，比较线芯、光晕、扫描纹的组合。
2. 用弦的 3D 声场原型验证空间结构、蓝橙关系、拉伸方向和真实文字落点。
3. 在 iPhone 上比较轻量 Metal 效果链与关闭效果的清晰度和 GPU 成本。
4. 再统一主界面、设置、设备选择和结果界面的线框组件、字阶、间距与交互状态。

这一轮的优先判断标准：主体一眼可辨、主操作两秒内可找到、中文清楚、蓝橙各有职责、细线有荧光感且黑底保持干净。
