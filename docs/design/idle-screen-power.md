# iOS 长待机界面休眠

主界面环境动画继续使用原来的 40 秒保持、4 秒渐停策略。`IdleScreenDimming` 独立管理当前 iMic 窗口的休眠遮罩：前台无操作 60 秒后，用 2 秒平滑将黑色遮罩的不透明度从 0 提高到 0.75；首次触摸开始时同步解除；录音状态或文字输入等程序活动唤醒时，最多用 0.16 秒平滑解除。

不再读取、保存或写入 `UIScreen.brightness`，也不判断系统亮度是否被使用者接管。此前的硬件亮度实现依赖保存原值，自动亮度漂移或手动调节可能使恢复路径丢失原值，导致继续使用时仍然偏暗。现在控制器只拥有遮罩透明度，系统亮度与自动亮度完全由系统和使用者管理，反复休眠不会逐轮压低亮度。

## 行为边界

- 任意触摸开始时同步解除遮罩，先于这次触摸继续投递给控件；同一次触摸继续操作原按钮或拖动，不需要先点一次唤醒。移动与松手通知不反复启动恢复动画。
- 多点触摸、持续按住、拖动、设置页与弹层均由窗口上的被动手势观察器记录。观察器不识别、不阻止、不取消其他手势。文字输入通知也重置闲置时间。动画时钟的唤醒共用这一观察器，移除主页原有的根部 `TapGesture`，避免用点击手势参与原生长按的竞争。
- 录音、识别和上传期间不进入休眠，结束后重新计算 60 秒。
- App 失去活跃状态时同步移除遮罩，取消截止任务与未完成渐变。`willResignActiveNotification` 和场景生命周期共同处理控制中心、锁屏及切换 App；回到前台时从明亮状态重新计时。
- 遮罩是当前 `UIWindow.layer` 上的黑色 `CALayer`，不新增窗口子视图、不参与触摸或辅助功能导航；根部观察视图随页面布局更新图层尺寸，窗口分离时销毁。透明度与尺寸写入禁用 Core Animation 隐式动画，避免有限渐变之外的延迟。原有自动锁屏策略不变。
- 系统亮度滑块的手动修改不被覆盖。控制中心使 App 失去活跃状态，因此关闭控制中心后看到的是没有遮罩的界面。

## 调度与验证

没有常驻 `Timer`、显示时钟或周期性轮询。控制器只有一个睡眠至闲置截止时间的 Task；操作更新最后活动时间，截止时按需再睡至新截止时间。渐暗和恢复仅在有限过渡期间以 30 Hz 更新透明度，完成后停止。遮罩不依赖波形显示时钟，也不为了变暗而重新唤醒已休眠的波形动画。

`scripts/test-screen-idle.sh` 注入透明度写入，覆盖刷新截止时间、单调渐暗、静止后零写入、首次触摸恢复、连续触摸不重启恢复、长按与忙碌保护、反复前后台与休眠、渐变中切后台及取消后无迟到写入。

`DisplayUITests.testIdleScreenRestoresOnFirstRecordingHold` 使用正式的 60 秒截止时间和 2 秒渐变，比较底部横条同一区域的截图亮度，检查界面确实变暗，再用第一次长按验证录音按钮仍能响应且界面恢复，随后打开设置、切后台并返回，检查回到前台仍然明亮。控制器状态和透明度记录在 `iphone.power` 日志中。

遮罩变化可以由截图验证；具体功耗改善仍需真机测量，不能将透明度比例视为节电比例，也不代表调低 LCD 背光。
