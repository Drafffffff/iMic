## 发现

### [P1] 设置页切换设备绕过会话取消，可把旧目标的缓冲录音发给另一台 Mac

- 位置：`ios/iMic/PairingSheet.swift:345`、`ios/iMic/LinkClient.swift:514`、`ios/iMic/SessionModel.swift:1087`
- 证据：设置页设备按钮直接调用 `link.connect(to: mac)`。该方法明确要求调用方先停止当前会话，但此入口没有调用 `cancelForDeviceSwitch()`。`closeConnectionLocked()` 也不通知 SessionModel 取消；新设备就绪后，`handleLinkReady()` 会继续补发当前缓冲。相比之下，设备页在 `DeviceSelectionView.swift:279` 和 `:328` 已提供确认与取消。
- 触发条件：已配对的目标 A 离线，在主页录音并松手，进入等待连接的缓冲状态；在连接超时前打开设置，从附近列表选择已配对且在线的 B。
- 后果：为 A 录制的音频会以新会话发送到 B，并可能在 B 的前台应用输入文字；用户没有确认取消或转交这段录音。
- 建议修复：让设置页复用设备页的选择流程，活动会话必须确认并先调用 `session.cancelForDeviceSwitch()`；同时在会话开始时绑定目标 ID，补发前再次核对。
- 置信度：高。

### [P1] VoiceOver 完成一次录音后无法再次开始录音

- 位置：`ios/iMic/HomeView.swift:747`、`:854`、`:726`
- 证据：辅助功能动作通过 `beginInteraction()` 将 `interactionStart` 设为 `true`；再次激活时只调用 `endListening()`，没有复位该标记。正常触摸路径通过 `HoldControl.onEnded` 复位，而 VoiceOver 激活路径不经过它。后续开始操作被 `guard !interactionStart` 拦截。
- 触发条件：正常主页中，使用 VoiceOver 双击录音条开始录音，再双击结束；结果返回后再次双击录音条。
- 后果：第二次录音没有响应。首次操作若因未连接、麦克风权限关闭或正在处理而提前返回，也会留下相同锁定状态。
- 建议修复：将触摸防重入标记限制在物理触摸生命周期内；为辅助功能提供独立的开始、结束路径，并在结束及失败返回时复位。
- 置信度：高。

### [P1] 授权等待期间松手没有撤销待执行的录音意图

- 位置：`ios/iMic/HomeView.swift:726`、`ios/iMic/SessionModel.swift:399`、`:412`、`:622`
- 证据：请求麦克风授权前设置 `wantsRecording = true`，但此时 `phase` 仍不是 `.listening`。录音条松手只在 `.listening` 时调用 `endListening()`，因此没有执行该方法入口处的 `wantsRecording = false`。授权任务随后仅检查该标记与应用是否 active，便启动采集。
- 触发条件：首次正式录音尚未取得麦克风权限，用户在授权完成前松手；授权任务恢复时应用已经 active。
- 后果：该条件成立时，用户已经松手，程序仍会进入录音并开始传输；原触摸已经结束，不会再收到对应的松手结束事件。`[推测]` 实机出现频率取决于系统授权回调与前台恢复的顺序，本次未验证该顺序。
- 建议修复：松手时无条件调用 `endListening(cancelled:)`，使等待授权阶段也能清除意图；授权任务另携带按压代际，松手、后台和页面离开都使其失效。
- 置信度：中。

### [P2] 上滑取消使用最后一次移动坐标，未核对松手的最终位置

- 位置：`ios/iMic/HoldControl.swift:57`、`:65`
- 证据：`translation` 只在 `touchesMoved` 更新。`touchesEnded` 先用旧值计算 `translation < -64`，随后仅更新横向触点位置，没有重新计算最终纵向位移。
- 触发条件：最后一次移动回调尚未越过取消阈值，但松手坐标已经越过。例如按下 `y=100`、移动到 `y=40`、最终松手在 `y=20`；现有逻辑仍按 `-60` 判定发送。`[推测]` 快速抬手或末次移动事件合并可产生这种序列。
- 后果：用户最终上滑超过取消阈值，录音仍可能被提交。
- 建议修复：在 `touchesEnded` 中先使用最终 `touch.location(in: self)` 和 `startPoint` 更新位移，再计算取消状态，并补充该事件序列的回归验证。
- 置信度：中。

## 已检查且未发现问题的方面

- **会话回调隔离**：结果、上传完成和超时路径使用活动会话编号及 `submissionGeneration`，能够拒绝已取消会话的多数迟到回调。
- **正式设备页保护**：切换和删除当前设备会确认取消活动语音；非当前设备删除有独立路径。
- **润色设置同步**：显示 Mac 确认的状态，保存期间禁止继续编辑；断线或切换目标会清除临时请求，手机不持久化另一套润色偏好。
- **引导恢复与练习隔离**：持久化的 `.release` 会恢复为 `.hold`；练习录音和输入在入口转入本地实现，避开真实采集与发送路径。
- **波形回放与存储**：播放任务有取消和代际检查；缓存校验帧数、时间及数值范围，删除与清空使用 epoch 防止迟到保存恢复数据。
- **本地化资源与动效守卫**：目录双语及占位符检查通过；主要渲染与手势物理存在减少动态效果的处理路径。未将固定英文技术标签直接列为缺陷。
